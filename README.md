## Запуск

Нужен запущенный Docker Desktop: в трее кит должен быть зелёным. Пока движок не поднялся, `docker compose` отвечает, что не находит `dockerDesktopLinuxEngine`.

```bash
git clone https://github.com/cdlinkin/pingpong.git
cd pingpong
cp .env.example .env
```

В `.env` достаточно пароля базы и секрета для токенов:

```env
POSTGRES_DB=pingpong
POSTGRES_USER=pingpong
POSTGRES_PASSWORD=secret
JWT_SECRET=любая-длинная-случайная-строка
LOG_LEVEL=info
LOG_FORMAT=text
MINIO_ROOT_USER=pingpong
MINIO_ROOT_PASSWORD=минимум-8-символов
```

```bash
docker compose up --build
```

Сначала стартует Postgres, потом контейнер `migrate` накатывает миграции и выходит, и только после этого поднимается приложение. Рядом поднимается MinIO для файлов: бакет `pingpong` создаётся при старте. Консоль MinIO: http://localhost:9001, логин и пароль из `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD`.

Откройте http://localhost:8080 и зарегистрируйте двух пользователей. Второго удобно завести в окне инкогнито: так видно, как сообщения ходят туда и обратно. Swagger: http://localhost:8080/swagger/index.html.

Кнопка «Кратко» зовёт Ollama на вашей машине, не в контейнере. Нужны `ollama pull qwen2.5:3b` и запущенный `ollama serve` на порту 11434. Если модели нет, чат работает, а кнопка скажет, что пересказ не получился.

`docker compose down` останавливает всё. Данные базы и файлы остаются в томах `pgdata` и `miniodata`. `docker compose down -v` удаляет и их.

### Без Docker для самого приложения

Базу проще всё равно держать в контейнере:

```bash
docker compose up -d pingpong-postgres migrate
```

Снаружи Postgres слушает порт **5433**, а не 5432, чтобы не спорить с Postgres на машине. В `.env`:

```env
DATABASE_URL=postgres://pingpong:secret@localhost:5433/pingpong?sslmode=disable
```

Файлы в этом режиме пишутся в папку `uploads`. Если нужен MinIO: `docker compose up -d minio` и в `.env`

```env
STORAGE=s3
S3_ENDPOINT=localhost:9000
S3_ACCESS_KEY=pingpong
S3_SECRET_KEY=тот-же-что-в-MINIO_ROOT_PASSWORD
```

Из корня репозитория:

```bash
go run ./cmd/app
```

Пересказ в этом режиме выключен, пока в `.env` нет `LLM_BASE_URL=http://localhost:11434/v1`.

### Переменные окружения

| | |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | база в контейнере |
| `DATABASE_URL` | нужна только при запуске без Docker; в compose собирается сама |
| `JWT_SECRET` | обязательна, без неё сервер не стартует |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error`, по умолчанию `info` |
| `LOG_FORMAT` | `text` или `json`, по умолчанию `text` |
| `HTTP_ADDR` | адрес сервера, по умолчанию `:8080` |
| `STORAGE` | `local` или `s3`, по умолчанию `local`; в compose `s3` |
| `UPLOAD_DIR` | папка для файлов при `STORAGE=local`, по умолчанию `uploads` |
| `S3_ENDPOINT` | адрес S3 без `http://` |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | ключи; для MinIO это `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` |
| `S3_BUCKET` | бакет, по умолчанию `pingpong` |
| `S3_USE_SSL` | `true`, если S3 по https |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | логин и пароль MinIO, пароль не короче 8 символов |
| `LLM_BASE_URL` | OpenAI-совместимый API, например `http://localhost:11434/v1`. Пустое значение выключает пересказ |
| `LLM_MODEL` | имя модели, по умолчанию `qwen2.5:3b` |
| `LLM_API_KEY` | ключ, если провайдер его требует. У локальной Ollama можно не задавать |
| `LLM_TIMEOUT` | сколько ждать модель, по умолчанию `60s` |

## Что умеет

Регистрация и вход по JWT, личные чаты и группы. Админ группы добавляет и удаляет участников. Сообщения идут через WebSocket, история подгружается кнопкой «Загрузить ещё», по чату есть поиск.

- Галочки: одна, если сообщение сохранено, две, если его прочитали. В списке чатов счётчик непрочитанных.
- Правка своего сообщения с пометкой «изменено» и удаление. На месте удалённого остаётся «Сообщение удалено».
- Ответ с цитатой. Клик по цитате прокручивает к оригиналу.
- Реакции 👍 ❤️ 😂 😮 😢 🔥. Одна на человека, повторный клик снимает.
- Упоминания `@логин` с подсказкой при вводе. Упомянутый видит значок «@», и это доходит даже в заглушённый чат.
- Колокольчик в шапке заглушает чат: сообщения остаются, пинга нет, бейдж серый.
- Картинки и файлы до 10 МБ: скрепка, перетаскивание или вставка из буфера. Картинки открываются на весь экран, остальное скачивается. Хранилище S3-совместимое (в compose это MinIO) или диск.
- Короткий access-токен тихо обновляется по refresh-токену. Выход отзывает refresh на сервере.
- «Кратко» пересказывает непрочитанное локальной моделью. Если адрес модели не задан, кнопка отвечает, что пересказ выключен.
- Лимит запросов по IP на вход и регистрацию, по пользователю на остальное и на сообщения в сокете.
- Остановка по `Ctrl+C` или `docker compose down` доделывает начатые запросы и закрывает сокеты.
- Логи через `log/slog`, текстом или в JSON.
- Swagger со всеми ручками и примерами.

### Тесты

```bash
go test -race ./...
```

Покрыты сервисы `auth`, `chats` и `messages` на фейковых репозиториях, валидация, JWT, middleware, хаб WebSocket и HTTP-хендлеры, включая сокет.

Интеграционный тест репозитория сообщений ходит в живую Postgres и в обычный `go test ./...` не входит. Нужен `DATABASE_URL` (локальная база из compose слушает порт 5433):

```bash
go test -tags integration ./internal/messages/ -count=1
```

Если поменялись swagger-аннотации:

```bash
swag init -g cmd/app/main.go -o docs --parseInternal
```

## Как устроено

Go 1.26 и стандартный `net/http`. Роутер `ServeMux` уже умеет методы и параметры в пути (`GET /chats/{id}/messages`), отдельный фреймворк не понадобился. Postgres через `pgx/v5`, миграции через `golang-migrate`, сокеты на `gorilla/websocket`, лимиты на `golang.org/x/time/rate`. Фронт это один `web/index.html`, его отдаёт тот же сервер.

```
cmd/app/          сборка зависимостей и роуты
internal/
  auth/           регистрация, вход, JWT, middleware
  chats/          чаты и участники
  messages/       сообщения, поиск, прочтения, ответы, реакции, вложения, пересказ
  llm/            клиент к модели (OpenAI-совместимый /v1/chat/completions)
  storage/        файлы на диске и в S3
  ws/             хаб соединений и обработчик сокета
  ratelimit/      лимитер по ключу и middleware
  logging/        slog и лог каждого запроса
  server/         запуск и остановка HTTP-сервера
migrations/
web/index.html
```

Внутри `auth`, `chats` и `messages` одна раскладка: `handler → service → repository`. Хендлер разбирает запрос и превращает ошибки в HTTP-коды, сервис проверяет права и правила, репозиторий пишет SQL. Сервис знает о репозитории только через интерфейс, поэтому в тестах вместо базы подставляется фейк. Модели из базы наружу не уходят: у ответов свои структуры.

### Путь одного сообщения

Клиент отправляет в сокет `{"chat_id": 13, "message": "Привет"}`. Сервер проверяет лимит и то, что отправитель состоит в чате, сохраняет сообщение и отдаёт хабу. Хаб рассылает его всем участникам, у кого сейчас открыто соединение. У одного человека может быть несколько вкладок, каждая получит своё. Отправителю сообщение тоже возвращается, и это подтверждение «доставлено».

Правка, удаление, прочтение и реакции идут через обычный HTTP, но рассылаются тем же хабом. Пакет `messages` видит хаб только через интерфейс `Notifier`, поэтому `messages` и `ws` не импортируют друг друга.

| Событие в сокете | Что значит |
|---|---|
| без поля `type` | новое сообщение |
| `message.edited` | сообщение изменили |
| `message.deleted` | сообщение удалили |
| `message.read` | кто-то дочитал чат до такого-то сообщения |
| `message.reactions` | поменялись реакции |
| `{"error": "..."}` | ошибка, приходит только отправителю |

**Пагинация по id, а не через `OFFSET`.** Клиент просит «20 сообщений старше id 120». Пока человек листает историю, новые сообщения не сдвигают страницы, а запрос идёт по индексу `(chat_id, id)`.

**Удаление мягкое.** На удалённое сообщение могут ссылаться ответы, поэтому строка остаётся с пометкой `deleted_at`, а текст перестаёт отдаваться. В поиск такие сообщения не попадают.

**«Прочитано» хранится одним числом на участника:** `last_read_message_id`. Число только растёт (`GREATEST`), так что старая вкладка не откатит прочтение назад.

**Реакция одна на человека.** Первичный ключ `(message_id, user_id)` и `INSERT ... ON CONFLICT DO UPDATE`.

**Файлы лежат в хранилище, в базе только описание.** Файл сохраняется под случайным ключом из 32 hex-символов, а настоящее имя, тип и размер пишутся в `message_attachments`. Тип определяется по первым байтам (`http.DetectContentType`) и сверяется со списком: картинки, PDF, ZIP, текст. Отдаётся файл только участникам чата, с `X-Content-Type-Options: nosniff`. Хранилище спрятано за интерфейсом `FileStorage` (`Save`, `Open`, `Remove`): `storage.Local` и `storage.S3`. При удалении сообщения его файл тоже удаляется.

**Два токена.** Access-токен: JWT на 15 минут, сервер проверяет его без базы. Refresh-токен: 32 случайных байта на 30 дней, в базе только его sha256. На `POST /refresh` старый refresh удаляется и выдаётся новая пара. Фронт на любой 401 делает один `/refresh` на все параллельные запросы и повторяет запрос.

**Лимиты разные.** На `/login`, `/register`, `/refresh` и `/logout` лимит по IP: 5 попыток, дальше раз в 12 секунд. Остальное считается по пользователю, сокет отдельно на каждое сообщение.

**Пересказ не знает, какая модель снаружи.** Сервис зовёт интерфейс `Summarizer` с одним методом `Complete`. Пустой `LLM_BASE_URL` оставляет интерфейс `nil`, и ручка отвечает 503. Текст пересказа нигде не сохраняется. Модель видит не больше 100 последних непрочитанных строк.

## API

Подробно с примерами в Swagger. Всё, кроме первых пяти ручек, ждёт заголовок `Authorization: Bearer <token>`.

| | | |
|---|---|---|
| POST | `/register` | регистрация |
| POST | `/login` | вход, в ответе access- и refresh-токен |
| POST | `/refresh` | новая пара токенов, старый refresh перестаёт работать |
| POST | `/logout` | отозвать refresh-токен |
| GET | `/health` | жив ли сервер |
| GET | `/me` | кто я |
| GET | `/chats` | мои чаты и сколько в каждом непрочитанных |
| POST | `/chats/direct` | открыть личный чат |
| POST | `/chats/group` | новая группа |
| GET | `/chats/{id}/members` | участники |
| POST | `/chats/{id}/members` | добавить участника, только админ |
| DELETE | `/chats/{id}/members/{userID}` | убрать участника, только админ |
| GET | `/chats/{id}/messages?before=&limit=` | история |
| POST | `/chats/{id}/messages` | отправить сообщение без сокета |
| GET | `/chats/{id}/messages/search?q=` | поиск |
| PATCH | `/chats/{id}/messages/{msgID}` | поправить своё |
| DELETE | `/chats/{id}/messages/{msgID}` | удалить своё |
| POST | `/chats/{id}/messages/{msgID}/reactions` | поставить или снять реакцию |
| POST | `/chats/{id}/attachments` | отправить файл |
| GET | `/attachments/{id}` | скачать файл, только участникам чата |
| POST | `/chats/{id}/read` | отметить прочитанным |
| GET | `/chats/{id}/reads` | докуда дочитал каждый |
| GET | `/ws?token=` | WebSocket |
| POST | `/chats/{id}/summary` | короткий пересказ непрочитанного |
